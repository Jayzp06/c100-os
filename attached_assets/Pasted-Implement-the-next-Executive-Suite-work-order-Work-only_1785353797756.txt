## 4. Bylaws Officer workspace

Build the governance document foundation before adding AI.

Features:

- Upload PDF and DOCX governance documents.
- Supported document categories:
  - Chapter Constitution
  - Chapter Bylaws
  - University/Institution Policy
  - National Organization Guidance
  - Standing Rules
  - Amendment
  - Other Governance Document
- Store:
  - title
  - category
  - version label
  - effective date
  - approval date, when applicable
  - status: draft, under\_review, current, superseded, archived
  - notes
  - original filename
  - MIME type
  - size
  - storage reference
  - uploader
  - created/updated timestamps
- Allow only one `current` version per document category where that rule is appropriate.
- Publishing a new current version must supersede the previous current version transactionally.
- Preserve full version history.
- Support download and preview when feasible.
- Allow the Bylaws Officer to create, edit, publish, supersede, archive, and restore documents.
- Give Parliamentarian read-only access to current published governance documents through a separate permission such as `view_governance_documents`.
- Do not implement AI, embeddings, vector search, or document Q&A yet.
- Design the schema so extracted text and indexing can be added later without redesigning document identity/version history.

## 5. Secretary workspace

Build official chapter-record tools:

- Meeting agenda records.
- Meeting minutes.
- Correspondence log.
- Meeting date, meeting type, title, status, notes, and attachments.
- Draft, submitted for approval, approved, and archived states.
- Record who prepared and approved each item.
- Allow editing while draft.
- Approved minutes must remain historically preserved; later corrections should create a revision instead of silently overwriting the approved record.
- Search/filter by date, meeting type, status, and record type.
- Export or download official records where the existing export system supports it.

Permissions should remain domain-specific, including `manage_minutes`, with additional precise permissions only when genuinely needed.

## 6. Treasurer workspace

Build financial recordkeeping tools, not banking integration:

- Budget categories.
- Income and expense ledger entries.
- Dues/payment tracking tied to a member when applicable.
- Receipt/document attachments.
- Transaction date, description, category, amount, direction, payment method, reference number, notes, creator, and status.
- Never store full card numbers, bank credentials, or sensitive payment authentication data.
- Validate monetary amounts using decimal-safe storage; do not use floating-point values for persisted currency.
- Dashboard totals:
  - budgeted
  - income
  - expenses
  - remaining
  - outstanding dues
- Filters by date, category, member, status, and transaction direction.
- CSV/XLSX/PDF exports using the already-fixed authenticated desktop export flow.
- Corrections should be traceable through audit history; do not silently mutate finalized financial records.

Gate this workspace and its APIs with `manage_finances` and narrower read permissions if necessary.

  - visibility
