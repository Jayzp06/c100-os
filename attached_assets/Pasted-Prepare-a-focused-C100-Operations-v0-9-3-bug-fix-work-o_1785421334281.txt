- Set a correct `Content-Disposition` filename on backend exports.
- Make web and desktop filenames consistent.

## 10. Desktop save-location picker

For Tauri desktop exports, allow the user to choose the filename and destination before saving.

Use supported Tauri v2 plugins/APIs:

- save-file dialog
- filesystem write support

Required flow:

1. User selects CSV, XLSX, or PDF.
2. App requests the authenticated export as bytes/blob.
3. App reads the backend’s suggested filename or builds the standardized filename.
4. Native Save dialog opens with:
   - suggested filename
   - correct extension
   - correct file-type filter
5. User chooses destination.
6. App writes the exact bytes to that path.
7. Show success with the selected filename.
8. If the user cancels, exit without an error.
9. If writing fails, show a safe actionable error.
10. Never write without an explicit user action.

Security and correctness:

- Reuse the existing authenticated Tauri export request.
- Do not expose bearer tokens.
- Do not convert binary XLSX/PDF data through text.
- Validate/normalize the selected extension.
- Do not overwrite an existing file without the native dialog’s normal confirmation behavior.
- Add only the minimal Tauri filesystem/dialog permissions required.
- Do not grant broad arbitrary filesystem access if a scoped permission is available.

Web behavior remains a normal browser download with the descriptive filename.
