The platform is now in Release Candidate status (v0.9.0-rc1).

Do not build any new modules, dashboards, workflows, automations, financial systems, governance systems, or database redesigns.

The objective of this batch is to finalize the administrator experience, improve usability, and polish the Executive Board demonstration while minimizing code changes and preserving platform stability.

This is a refinement pass, not a feature expansion.

Part 1 — Modernize Member Permissions

Replace the current single-select Role dropdown with a modern multi-tag permission system.

A member may legitimately hold multiple permissions simultaneously.

Examples include:

Member
Committee Chair
Technology Chair
Parliamentarian
Historian
Bylaws Officer
Executive Officer
President
Vice President
Secretary
Treasurer
Administrator
Platform Administrator

Display these as removable tags/chips rather than a dropdown.

Example:

Permissions

[Member] ×
[Committee Chair] ×
[Technology Chair] ×

Users should be able to:

Add permissions
Remove permissions
Save changes

Maintain full backward compatibility with the existing RBAC implementation.

Do not break existing permissions.

Separate Permissions from Organizational Assignment

Committee assignment is not a permission.

Keep Committee as its own field.

Example:

Committee

▼ Mentoring

This remains independent from permission tags.

Executive Officer Cleanup

Do not use generic "ExecutiveBoard" as a selectable permission.

Instead:

Executive Board membership should be derived automatically from executive officer permissions.

For example:

President

Vice President

Secretary

Treasurer

Chief of Staff (future)

Sergeant-at-Arms (future)

Technology Chair

etc.

The system should understand that these positions collectively represent Executive leadership rather than requiring a generic ExecutiveBoard role.

Do not redesign RBAC.

Only improve the administrative UI and permission assignment model.
