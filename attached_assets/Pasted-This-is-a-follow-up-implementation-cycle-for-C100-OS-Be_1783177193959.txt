==================================================
PHASE 4 — FORM DATA ARCHITECTURE
==================================================

Divide Facilities Use Form information into four categories:

A. CHAPTER PROFILE DATA

B. EVENT DATA ALREADY STORED IN C100 OS

C. ADDITIONAL FACILITY REQUEST DATA ENTERED BY THE USER

D. OFFICE USE ONLY DATA

Each category must be handled differently.

==================================================
A — CHAPTER PROFILE DATA
==================================================

The following information should be stored centrally in C100 OS chapter/system settings.

Authorized administrators should be able to configure this information once.

Where applicable, automatically insert it into every Facilities Use Form.

Fields include:

SPONSORING ORGANIZATION INFORMATION

- Organization or Department
- Default Contact Person, if appropriate
- Address
- Contact Number
- Contact Number Type
- Email
- Fax, if applicable

FACULTY/STAFF ADVISOR INFORMATION

- Faculty/Staff Advisor Name
- Campus Address
- Home Address, if the chapter chooses to store it
- Contact Number
- Contact Number Type
- Secondary Contact Number, if applicable
- Email
- Fax, if applicable

IMPORTANT PRIVACY REQUIREMENT

Do not require unnecessary sensitive personal information to be stored.

If Home Address or other personal information is not necessary for C100 OS operation, allow the field to remain blank and be entered manually when generating the form.

Do not expose Advisor personal information to unauthorized users.

==================================================
B — EVENT DATA ALREADY STORED IN C100 OS
==================================================

When generating a Facilities Use Form from an existing event, automatically populate all available information already stored in C100 OS.

This includes:

- Sponsoring Organization
- Contact Person, where appropriate
- Contact Email
- Event Date
- Detailed Description of Event
- Requested Area
- Room
- Start Time of Event
- End Time of Event
- Expected/Estimated Attendance
- Sponsoring Committee
- Event Owner

If event creation already collects setup and cleanup times, use those values.

Otherwise, extend the event/facility request architecture to support them.

The user should not need to repeatedly type information C100 OS already knows.

==================================================
C — ADDITIONAL FACILITY REQUEST DATA
==================================================

When an authorized user selects:

Generate Facilities Use Form

open a workflow containing only information that is missing or must be confirmed.

The workflow should collect the following information from the official form.

ADVISOR ATTENDANCE

- Will Faculty/Staff Advisor attend the event/activity?
- Yes
- No

If No:

- Which advisor(s) will chaperone the event/activity?
- Attending Advisor
- Attending Advisor Contact Number

EVENT LOGISTICS

- Time to Start Setup
- Time to End Cleanup

FUNDRAISING

- Is this a fundraiser?
- Yes
- No

ADMISSION OR REGISTRATION

- Is there an admission or registration fee?
- Yes
- No

If Yes:

- Fee Amount

FOOD

- Will food be served?
- Yes
- No

If Yes:

- Who is preparing the food?

AUDIENCE

Allow selection of one or more:

- FVSU Students
- FVSU Faculty
- FVSU Staff
- FVSU Alumni
- Graduate Students
- General Public
- Prospective Students
- Community Youth
- Community Adults
- Academic/Professional Associates

BUILDINGS AND GROUNDS REQUIREMENTS

- Number of Tables
- Number of Chairs
- Staging Size
- Earliest Date Setup Can Be Completed
- Earliest Date Setup Can Be Disassembled
- Housekeeping Requirements
- Comments

Use conditional form logic.

Examples:

If Fundraiser = No:

Do not request unnecessary fundraising information.

If Admission Fee = No:

Hide or disable Fee Amount.

If Food Served = No:

Hide or disable Food Preparation information.

If Advisor Attending = Yes:

Do not require alternate chaperone information.

PHASE 5 — FACILITY REQUEST UX
==================================================

The workflow should be simple for Committee Chairs and other authorized event creators.

Recommended workflow:

1. User creates an event.

2. Event information is saved in C100 OS.

3. User selects:

Generate Facilities Use Form

4. C100 OS retrieves:

- chapter information
- advisor information
- event information
- contact information

5. C100 OS displays only missing or confirmable Facilities Use Form information.

6. User completes the additional fields.

7. User selects:

Preview Form

8. C100 OS generates a preview.

9. User selects:

Download Completed Form

10. C100 OS exports the official FVSU Facilities Use Form as a completed PDF.

The user should NOT need to manually copy event information from C100 OS into the PDF.
